# まるシマリバーシ 作業記録

最終更新：2026-10-25（段階3：中継サーバー・合成音声・おばあちゃん側の画面）

遠くに住むおばあちゃんと小1の孫が、ビデオ通話で顔を見ておしゃべりしながら遠隔対戦するリバーシ。iPad の Safari で遊ぶ（Android の Chrome も可）。将来は Capacitor で包んで App Store／Google Play に出す。

## 決まったこと

- 名前は「リバーシ」（「オセロ」は商標のため使わない）。仮題「まるシマリバーシ」
- 呼び名は使わず「くろ」「しろ」で呼ぶ。先手はくろ。対局ごとに子とおばあちゃんでくろを交代
- 取れる枚数は表示しない（多く取れる手が良い手とは限らない）
- 盤は緑・黒い線・4つの星・濃いグレーの枠。置ける場所はミント色のリング、最後に置いた石の下に赤い光（次の手まで残る）
- 石は厚みのある円柱として返す（側面は半分黒・半分白）
- 手加減はおばあちゃん本人がやる（CPU なし）
- キャラ：まるシマ＝子の相棒、めえばあ＝おばあちゃんの相棒、ぽにー＝進行（パス・まった・もういっかい）、かめじい＝審判（はじめ・数え・勝敗）
- 声：ぽにー＝VOICEVOX 調整版（ことばのたねと同じ）、かめじい＝AivisSpeech。`voice/out/*.mp3` がないときだけ端末の読み上げ
- 確認用：URL の末尾に `#pass`（パス直前）、`#end`（終局直前）
- 盤の外を3秒ながおしで設定（テンポ・光・音量）

## 遠隔対戦（段階2）のしくみ

- 親機で「たいせんあいてを よぶ」→ QR と「LINEで おくる」が出る。おばあちゃんはリンクを開いて「はじめる」→ カメラ・マイクを「きょか」→ つながる
- 親機（こども・まるシマ側）が「ホスト」、おばあちゃん（めえばあ側）が「ゲスト」。それぞれ自分の側しか打てない。まったボタンも自分の席だけ
- 顔はそれぞれの席の上に出る（自分は小さく左右反転、相手は大きく）
- 盤は「手の履歴」で同期。ずれたらホストの履歴に合わせる
- まった：自分の直後の手は すぐもどる。相手が打ったあとは相手に「いいよ／だめ」をきく（10秒で だめ扱い）。こどもからの まったは設定「じどうで いいよ」（初期値）なら きかずにもどる
- もういっかい：二人とも押したら始まる。くろを交代
- 切れたとき：席に「つなぎなおしています…」、ぽにー「ちょっと まってね」。ゲストは自動で つなぎなおす。リンクをもう一度開いても同じ部屋・同じ対局に戻る。部屋は3時間つかいまわす
- つなぐ前の紹介役は PeerJS の公開サーバー（無料）。モバイル回線どうしでつながらないときの中継サーバー（TURN）は段階3
- 確認用：`?ps=127.0.0.1:9000` で手元の紹介役サーバーを使える。2台ぶんの自動テストは headless Chromium のにせカメラで実施済み（打つ・まった2種・切断と再接続・もういっかい）

## 段階3（2026-10-25）

- **中継サーバー（TURN）**：Metered の無料「Open Relay」を共有の鍵（static auth）で使う。月20GBまで。合言葉はその場で作る（`net.js` の `turnServers`）。ストア版では自前のアカウント（API キー）に切り替える
- **中継のテスト**：設定「つながり方」を「中継だけ」にして「たいせんあいてを よぶ」→ 家の中でも必ず中継を通る。つながれば家の外でもつながる。設定画面に「いまのつながり：直接／中継サーバー」が出る
- **声**：台本 `voice/gen_lines.py` → `voice/pony.json`（ぽにー9本）・`voice/rv1/`（かめじい134本：はじめ・勝敗・「くろが Nこ」「しろが Nこ」0〜64）・`voice/lines.js`（吹き出しの文）。GitHub Actions `reversi-voice`（`reversi/voice` を push すると動く）が合成して `reversi-voice-out` ブランチに置く → `voice/out/` にコピーする
- **おばあちゃん側**：リンクに `openExternalBrowser=1` を付けて、LINE の中ではなく Safari で開くようにした。最初の画面は漢字まじりの大きな文字で「お誘いです／1. はじめる 2. 許可」。カメラを許可しなかったときは設定の直し方を出す
- つながり直したら、ぽにー「つながったよ！ つづきから やろう」

## はでな演出（2026-11-03）

- 返す石は1列にならべて（置いた石に近い順）1枚ずつ返す。だんだん速く、1枚ごとに演出が豪華になる（火花→3枚目から輪→5枚目から星→7枚目から光の筋→9枚目から盤がゆれる。音もペンタトニックで上がり、重なる）
- 最後の1枚が見せ場。全体の枚数で段階を重ねる：3枚〜＝輪・和音／5枚〜＝光の筋・星・ゆれ・低音／8枚〜＝フラッシュ・紙ふぶきの雨・星が石の数へ飛ぶ・シンバル／12枚〜＝花火3発・ファンファーレ
- 置いた石そのものは はじけない（2026-11-03 あまねさんの指示）
- 勝ったとき：画面を夜空にして、勝った側の上を中心に約7秒の花火＋紙ふぶき、勝った席が金色に光る。ひきわけは両方に少し
- 設定「えんしゅつ」：はで（初期値）／ひかえめ（ゆれ・フラッシュ・夜空なし、粒は少なめ）
- 枚数の数字は出さない（多く取るのが良い手とは限らないため。演出の大きさだけで伝える）

## 2026-11-03 なおし

- **LINEで おくる**：iPad の「共有」画面を出して LINE を選ぶ形にした。共有画面はリバーシの上に重なるだけなので、送ると自動でリバーシに戻る（前は LINE のページが別タブで開き、戻れなかった）。共有画面がない端末だけ LINE アプリを直接開く
- **音が鳴らない**：iPad のマナーモード対策（ことばのたね と同じ）。1台のときは audioSession=playback＋audio 要素経由、通話のときは play-and-record。画面にさわるたび・カメラが入ったあと・画面に戻ったときに音を再開
- **声の前後の無音**をけずった（例：はじめ 4.3秒→3.6秒）
- **1台で遊んでいる途中で相手をよんだら**、とちゅうの盤はすてて新しい対局から（くろ＝こども）
- **少ない枚数は控えめに**（2026-11-03）：演出と音の強さを 枚数で 0.3〜1 倍に。11枚以上で前と同じ最大
- **音をしぼった**（2026-11-03）：鳴らすのは 置く音・返す音・返すときの演出の音（最後の1枚の段階の音、12枚以上の花火）と 勝ったときの花火の音だけ。手番のチャイム、まったのシュッ、いいよ／だめ、数えるときのコロコロ、勝ち負けのファンファーレ、キャラの演技の小さな音（ことばのたね由来）はやめた
- **メニューに もどる**（2026-11-03）：画面の上のまん中に「メニュー」ボタン（ゲームが始まると出る）。押すと「ゲームを やめて メニューに もどる？」→「やめる」で盤をすてて はじめの画面へ（ページを読みなおす）。遠隔対戦なら相手にも知らせ、カメラと通話を止める。相手の画面には「あいてが おわりにしました」＋ぽにー、そのあと はじめの画面へ
- 縦持ちで「まい」が数字から離れていたのを直した
- **リンクを開いたら いつも最初から**（2026-11-03）：前回のとちゅうの盤は読みこまない。例外は遠隔対戦のとちゅうで おばあちゃん側がつなぎなおしたとき（ホストの盤に合わせて続きから）

## 遠隔対戦の点検（2026-11-04）

なおしたこと：
- 同じリンクを2つの画面で開いたとき、あとの画面が つながっている画面から相手を うばわない（「ほかの がめんで つながっています」。10秒ごとに入りなおしを試すので、前の画面を閉じれば自動でつながる）
- カメラかマイクの片方が使えなくても、使えるほうで通話する。ホストにカメラもマイクもないときは、ゲストのほうから通話をかける（ゲストの顔はホストに映る）
- 相手のカメラが映らないとき「あいての カメラが うつりません（ゲームは できます）」
- ゲストが30秒つながらないとき「あいての iPad で『たいせんあいてを よぶ』の画面が ひらいているか たしかめてね」
- iPadOS 16.4 より前（Wake Lock なし）は、音なしの小さな動画（`lib/nosleep.mp4`）をくりかえし流して画面が消えるのをふせぐ
- iPadOS 15.4 より前の Safari 向けに `Array.prototype.at` をおぎなう

まだ確かめていないこと（実機で）：中継サーバー（Open Relay）でつながるか／おばあちゃんの iPad の iPadOS バージョン／マナーモードで音が出るか

## 2026-11-05 作り込み

- **盤と石を本物のオセロに近づけた**：フェルトの織り目（`src/felt.txt`＝タイル画像、build.py が埋めこむ）、少し沈んだフェルトと面取りのある黒い枠、手前からわずかに見おろす角度（rotateX 4°）。石は艶のあるプラスチック（ドーム状のハイライト・ふちの暗さ・クリームがかった白）、手前に見える厚みの帯（上半分は上面の色、下に反対の色がのぞく）、フェルトに落ちる影。返すときは 32面の円柱（厚みは直径の17%＝本物の34mm・6mmに近い）に ふちの丸みと、石が立つと細くなる影
- **演出と音は指数関数的**：強さ amp(n)=min(1, 0.08×2^((n−1)/2.75))。1枚 0.08・4枚 0.17・7枚 0.36・10枚 0.77・11枚以上 1.0。輪は5枚以上、星は7枚以上、光の筋は9枚以上のときだけ。段階：5枚〜＝2、7枚〜＝3、9枚〜＝4、12枚〜＝5
- **遠隔対戦は10回まで無料、11回目から解放（買い切り）**：`src/billing.js`。回数は よぶ側（ホスト）の端末で、対局が始まるたびに数える（もういっかい も1回、つなぎなおしは数えない）。**どちらかが解放ずみなら遊べる**（つながったときに「解放ずみか」を知らせ合う `lic`。解放ずみの人がいれば数えない）。無料分が終わり どちらも未解放なら、両方の画面に解放の案内（`locked`）。どちらかが解放すると（`lic`→ホストが再判定→`unlocked`）そのまま始まる。Web 版では購入できない（案内のみ）。ストア版では `window.MarushimaIAP`（purchase／restore）をネイティブ側で用意して App Store／Google Play のアプリ内課金につなぐ。開発用に設定「テスト用に解放」（ストア版では外す）。ストア・課金の管理はうちのあじと同じアカウント（Apple Developer UCHINOAJI・Google Play Console うちのあじ）
- 開始画面の「遠隔対戦：あと N回 むりょう」は のこり3回からだけ出す（解放ずみなら出さない）、右下に版（日付＋コミット。iPad で古い版が出ていないか確かめる用）
- 手番で18秒考えこんだら 相棒が指さし、置ける場所の光が強くなる（25秒ごとにくりかえす）。開始画面では まるシマが手をふる

## 2026-11-05 対戦相手の登録

- **部屋は端末に固定**（`net.js`）：前は3時間で部屋が変わり、毎回あたらしいリンクを LINE で送る必要があった。いまは一度送ったリンクがずっと使える（設定「あたらしい部屋にする」で作りなおしたときだけ変わる）
- **ゲスト側の登録**：リンクを開くと、その部屋と相手の名前（リンクの `&n=` ＝ホストの設定「相手の画面に出る自分の名前」）を端末に保存（`marushima-reversi-partners`、5人まで）。つぎから開始画面に「登録ずみ ○○と 対戦する」ボタンが出て、LINE のリンクなしで入れる。設定「登録を けす」で消せる
- **ホスト側**：ゲストが一度でも登録すると（`hello{reg:true}`）、「たいせんあいてを よぶ」はリンクの画面を出さず「登録ずみの あいてを まっています…」で待つ（「リンクを おくる」ボタンで必要ならまた送れる）。初回と「あたらしい部屋にする」のあとは今までどおりリンク／QR を出す
- どちらが先に開いても つながる（ゲストが先に「○○と 対戦する」を押して待っていてもよい）
- 確認：partner.py（初回はリンク表示→ゲスト登録→2回目はリンクなしで同じ部屋→ボタンで接続、ゲスト先行でも接続）、net2／net3／menu／bill は変わらず通る
- **なまえの画面**（同日）：開始画面の「なまえを きめる／なまえ：○○（かえる）」と設定の「名前を変える」から。自分の名前（相手の画面の「○○と 対戦する」に出る）と、この端末に登録した相手の名前を変えられる。名前が未設定のまま「たいせんあいてを よぶ」を押すと先にこの画面が出る。よぶ側が名前を変えると、つながったときに相手側のボタンの名前も新しくなる（`hello{name}`）

## 2026-11-07 電話のあと音が消える／本体が熱くなる

- **電話のあと音が消える**（iPhone）：AudioContext が "interrupted" のまま resume しても戻らないことがある。一度 resume を試して1.5秒たっても鳴らせなければ、次にさわったときに音の出口ごと作りなおす（`rebuildAudio`。効果音の master も作りなおし）。戻るボタンなどで古い画面がそのまま復元されたとき（bfcache）は読みなおす
- **電話のあとカメラ・マイクが止まったまま**：線が ended／muted のままなら取りなおして、通話中なら `replaceTrack` で新しい線に差しかえる（`NET.refreshMedia`。線の ended と、画面に戻ったときに実行）。相手の映像・声の要素も再生しなおす
- **発熱**：毎フレームの処理を 30fps までに（120Hz の iPhone で 4分の1）。位置決め（getBoundingClientRect）は大きさが変わったときだけ。演出のキャンバスは描くものがないときさわらない
- 確認：recover.py（線を止めて取りなおし→送信側が新しい線に、音の出口の作りなおし、rAF 約35/秒）、net2／net3／menu／bill／names は通る（テストは名前を先に入れるように変更）

## 2026-11-07 その2：まだ音が出ない／まだ熱い

- **音の出口を作りなおし**：作った音を audio 要素（MediaStream）に通すやり方をやめ、無音の WAV を audio 要素でくりかえし流す方法（unmute.js と同じ）に。Web Audio はふつうの出口につなぐ。さわるたび・画面に戻るたびに audioSession の種類を設定しなおし、止まっていたら resume、前にさわっても戻らなかったらその場で作りなおす（pointerdown／touchend）
- 設定に「音の テスト（なおす）」：出口を作りなおしてポンと鳴らし、状態（running など・audioSession の種類・マナーモード対策・作りなおした回数）を出す。実機で原因を見る用
- **発熱（その2）**：じっとしているキャラは描きなおさない（動き・声・まばたき・ばねの揺れがあるときだけ。まばたきの直前は描く）。盤の上のキャラ（ぽにー・かめじい）は隠れているあいだ display:none で描かない。手番の光は box-shadow を動かさず、::after の透明度だけ動かす（GPU だけで済む）。キャラの描きなおしは 待ち時間で 2体あわせて約22回／秒（前は30fps×4体、その前は 120Hz×4体）
- **Android は最初の対局だけ無音**（同日、Android×iPhone で確認。「もういっかい」のあとは鳴った）：カメラ・マイクを使う前に作った音の出口が、通話が始まると動いたまま無音になるらしい。Android（iOS 以外）だけ、自分のカメラが入ったとき・相手の映像が届いたときに出口を作りなおす（`freshForCall`。ページで一度操作していればその場で、まだなら次にさわったとき）。iPhone・iPad はさわらない。発熱は解決と報告あり

## 2026-11-07 よびだし（通知で直接よぶ）

あまねさんの方針：アプリ化したとき毎回 LINE で呼ぶのは面倒。最初の登録だけ LINE、2回目からはゲームから直接よぶ。着信は「ふつうの通知（着信音つき）」で（電話風の CallKit 画面は必要になってから）。まず Web 版で作る。

- **中継**：Supabase の uchinoaji プロジェクトに Edge Function `rv-push`（ソースは `server/rv-push/index.ts`）と表 `rv_devices`・`rv_config`（RLS あり・ポリシーなし＝service role だけ）。うちのあじ本体とは無関係。VAPID の鍵は `rv_config`。いたずら防止に1時間30回まで。確認用に pg_net を有効にした（DB から関数を呼んで試験。テスト用の行 testdevA/B が残っている）
- **端末の名乗り**（`src/call.js`）：この端末で作った id と secret（`marushima-reversi-dev`）。つながったとき `{t:"dev"}` で おたがいの id を教えあう。ゲスト側は登録した相手（partners）に、よぶ側は `marushima-reversi-callers` に覚える
- **よぶ**：よぶ側の「○○を よぶ」（相手の端末を知っていると「たいせんあいてを よぶ」がこの名前になる）→ 相手に通知「ゆうくんから よびだしです」→ タップすると `?r=部屋&ring=1` が開いて「はじめる」。ゲスト側の「○○と 対戦する」→ よぶ側に通知 → タップで `?ring=1&fd=端末` が開き「ばあばから よびだし！」「ばあばと つなぐ」。60秒でつながらなければ取り消して「でられない みたい」。通知が届かない端末なら「リンクを おくってね」
- **通知の受けとり**：はじめの画面の「よびだしを うけとる（通知を ゆるす）」、設定の「よびだし」の欄。Service Worker は `sw.js`（90秒より古いよびだしは出さない、タップで その画面に移る）

## 2026-11-08 Android の通話中の無音（その2）と iPhone の発熱（その3）

- **Android で効果音・声が出ない（iPhone×Android、Android が呼ばれ側）**：出口を作りなおすだけでは直らなかった。Android は通話中「通話モード」になり、Web Audio の音（メディアの線）が消される端末があると見て、音を MediaStream にして audio 要素で鳴らす＝相手の声と同じ「通話の線」に乗せる（`routeViaCall`。`OUTN()` で出口を差しかえ、rig の `ctx.destination` も build で `OUTN()` に）。iPhone・iPad は使わない。音のテストの行に「通話の線」と出る
- **iPhone の発熱（5局で熱い）**：映像の符号化が原因と見る。SDP で H.264 を先に並べる（iPhone はハードウェア符号化。VP8 はソフトウェアで熱い）＋ `b=AS:300`、つながったら送信側に maxBitrate 250kbps・maxFramerate 12・maintain-framerate、カメラは 12fps（最大15）。`tuneSdp` は合成 SDP で並べかえを確認（手元の Chromium は H.264 なしなので実機で）
- 確認：codec.py（上限値・b=AS・通話の線に音が流れる）、net2／net3／recover／andr は通る
